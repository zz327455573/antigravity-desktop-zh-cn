# Antigravity 汉化与云电脑适配架构说明

## 1. 架构总览

Google Antigravity 是一款基于 Electron 的 AI Agent 桌面客户端。本汉化增强包采用**全链路分层注入机制**，覆盖从底层窗口管理、主进程菜单到渲染进程 DOM 的全维度本地化：

```
                    ┌────────────────────────────────────────┐
                    │      Antigravity.exe (Electron)        │
                    └───────────────────┬────────────────────┘
                                        │
           ┌────────────────────────────┴────────────────────────────┐
           ▼                                                         ▼
┌───────────────────────┐                                ┌───────────────────────┐
│     主进程 (Main)      │                                │    渲染进程 (Renderer) │
├───────────────────────┤                                ├───────────────────────┤
│ • utils.js (ICE 标题栏)│                                │ • preload.js 物理隔离  │
│ • ipcHandlers (容错)   │                                │ • 容器向上回溯算法     │
│ • menu.js (应用主菜单) │                                │ • MutationObserver    │
│ • tray.js (任务栏托盘) │                                │ • 动态文本翻译字典     │
│ • updater.js (更新弹窗)│                                └───────────────────────┘
└───────────────────────┘
```

## 2. 独家特性：移动云电脑 ICE 模式原生标题栏适配

### 痛点根因
在移动云电脑、华为云电脑、天翼云电脑等虚拟桌面环境（尤其是采用 Elink ICE 远程画面投射协议，display_type=1）下，Electron 默认的无边框自定义标题栏（Web 伪窗口控件）无法被远程桌面客户端的输入与手势捕获系统正确识别，导致：
- 窗口右上角放大、还原、最小化、关闭按钮完全失效；
- 窗口无法双击最大化或正常拖拽吸顶。

### 治本方案
在 `dist/utils.js` 中拦截 `createWindow` 配置：
```javascript
titleBarStyle: isMacOS() ? 'hidden' : undefined,
titleBarOverlay: false,
frame: true, // 启用 Windows 原生标准边框与标题栏
```
同时在 `dist/ipcHandlers.js` 中对 `win.setTitleBarOverlay` 注入 `try-catch` 容错，防止原生标题栏模式下触发未捕获异常。

## 3. 渲染层物理隔离安全引擎 (V12.0)

### 为什么需要容器向上回溯？
AI 编程助手（Agent）的核心场景是处理代码、Diff、终端输出。如果进行简单的字符串全量替换，必然会导致：
- 用户的代码中的英文单词被意外替换为中文；
- 终端运行命令、环境变量输出被破坏；
- Markdown 语法标签与代码块高亮失效。

### 隔离策略
本引擎在 `preload.js` 中实现**容器向上回溯算法**：
1. **禁区识别**：遇到文本节点时，向上遍历其父级容器元素；
2. **标签与类名过滤**：若匹配 `code`, `pre`, `textarea`, `input`, `.monaco-editor`, `.terminal`, `.diff-view` 等禁区属性，一律拦截并跳过翻译；
3. **精准匹配与模糊兜底**：先走严格哈希字典（O(1) 查找），再对特定长段落走结构化规则替换；
4. **零性能损耗**：基于高效的 `MutationObserver` 增量队列，界面渲染平滑无卡顿。
